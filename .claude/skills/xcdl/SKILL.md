# xcdl — µOS++ IIIe

## When to Use

- A source file, a public include folder, a compiler/linker option
  or a dependency is added, removed, or renamed, and
  `xcdl-package.jsonc` and `xcdl-test.jsonc` must be updated.
- The user asks what a property of `xcdl-*.jsonc` does, or why the
  top-level `CMakeLists.txt` or `meson.build` contain a given entry.
- A macro listed in `xcdl-*.jsonc` (a `defaultDefine`) is discussed,
  for example to decide whether it is enabled.

Read `.github/skills/project-defaults.md`, `.github/skills/project.md` first, and `project.md` in this
folder, if it exists; their rules extend these, and take precedence
where they differ.

## Current Status

The `xcdl` tool is not yet available; `xcdl-*.jsonc` is used only
to generate the top-level and tests CMake and Meson files, with:

```sh
xpm run xcdl-export
```

## Manual edits

The generated top-level `CMakeLists.txt` and `meson.build`, and those
in the tests `sources` folders, must not be edited by hand; change `xcdl-*.jsonc` and run
the action again.

## Properties

The two exporters read different sets of properties.

In `xcdl-package.jsonc` (the top-level files, generated by
`maintenance/scripts/xcdl-export.mjs`), the properties that affect the
generated files are:

- `publicIncludeFolders`, `sourceFiles`, `dependencies`, and `alias`;
- `publicDefines` and `privateDefines`;
- `publicCompilerOptions` and `privateCompilerOptions`, each a map of
  categories (`target`, `optimisations`, `warnings`, `debugging`,
  `miscellaneous`, and `linker`) with arrays of strings; the `linker`
  options go to the link options, the others to the compiler options;
- `cdlArtefacts`, which selects the static and object libraries.

In `xcdl-test.jsonc` (the files in the tests `sources` folders,
generated by `tests/scripts/xcdl-export.mjs`), only
`publicIncludeFolders`, `sourceFiles`, `publicDefines`,
`publicCompilerOptions` (a plain array of strings, not a map of
categories), and `dependencies` affect the generated files;
`description` is copied into a comment.

All the other properties (`generatedFile`, `activeIf`, `defaultValue`,
`implements`, and the commented-out `defaultDefine` entries) are
informative only. The exporters do not check the property names: a
property they do not read, for example `compilerOptions` written
instead of `publicCompilerOptions`, is ignored without any warning,
and its values do not reach the generated files.

## Macros

No `*-defines.h` file is generated, so a commented-out `defaultDefine`
does not mean that the macro is disabled. Its name documents the macro
that the application must define itself, either in
`micro-os-plus/project-config.h` or in project specific header files
(for example `micro-os-plus/startup-defines.h`).
